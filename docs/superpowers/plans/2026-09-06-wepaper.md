# wePaper Implementation Plan

> **Historical.** The public site no longer “renders papers with PDF.js” on the default path. See [CHANGELOG.md](../../../CHANGELOG.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a public HTTPS personal paper library synced from a Zotero collection.

**Architecture:** Read-only Zotero Local API daemon uploads metadata + PDFs to an authenticated FastAPI server; the public site lists papers and renders them with PDF.js.

**Tech Stack:** Python 3.12, FastAPI, SQLite, Alembic, Vite, React, pdfjs-dist, pytest, Playwright, nginx, Let’s Encrypt.

## Global Constraints

- Never write Zotero data or `zotero.sqlite`.
- Public read ≠ private write. Sync secret never enters the frontend bundle.
- Filenames are not identities. Use Zotero keys + content hash.
- Collection removal hides; permanent delete tombstones.
- No secrets, local DBs, or private PDFs in git.
